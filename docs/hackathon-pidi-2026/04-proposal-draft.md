## 6. Proposed Solution

## 7. Proposed Solution — Cara Kerja

**Bagaimana Solusi Bekerja? (input → proses → output)** _(≤900 kar — ±720)_:

> **Input:** pengguna memilih bahasa + tingkat tutur (mis. Jawa, Halus), lalu mengetik/berbicara (mis. "buatkan ucapan untuk simbah"). **Proses:** server menyusun _system prompt_ khusus bahasa+tingkat tutur, menggabungkan riwayat percakapan, lalu memanggil LLM berdaulat (SEA-LION; fallback Groq/OpenAI) via API OpenAI-compatible. Jawaban dialirkan token-per-token (SSE streaming). Untuk suara, server menerbitkan _ephemeral token_ dan browser terhubung realtime (WebRTC) ke model suara—transkrip tampil live. **Output:** balasan dalam bahasa daerah yang benar secara budaya (krama alus), lengkap tombol Salin & Suara, tersimpan sebagai riwayat. Untuk UMKM/Pemda, alur yang sama dibungkus jadi chatbot lewat Studio, atau dipanggil lewat API.

## 10. Technical Approach

**Teknologi Utama** _(≤700 kar — ±470)_:

> AI/LLM (SEA-LION `Llama-SEA-LION-v3-70B-IT`, Sahabat-AI; fallback Groq `llama-3.3-70b-versatile` & OpenAI `gpt-4o-mini`), suara realtime (OpenAI Realtime API via WebRTC) + Web Speech API (mode gratis). Web app: React 18 + Vite + TypeScript + Tailwind. Backend: Node.js + Express + TypeScript + Zod + JWT. Database & Auth: Supabase (PostgreSQL + Drizzle ORM). Streaming SSE. Deploy: Nginx + PM2 + Let's Encrypt.

**Pemilihan & Penggunaan Teknologi** _(≤600 kar — ±470)_:

> Kami memilih LLM berdaulat Indonesia/ASEAN agar selaras kedaulatan data & kualitas bahasa lokal. Semua provider **OpenAI-compatible**, jadi bisa berpindah model tanpa ubah kode—menghindari vendor lock-in dan menekan biaya. Konteks budaya disuntikkan lewat _system prompt_ per bahasa (cepat & murah, tanpa retrain). Supabase mempercepat auth+DB berkelas produksi. Arsitektur ini realistis dibangun tim kecil namun tetap scalable.

## 11. Technical Approach (lanjut)

**Algoritma Solusi** _(≤700 kar — ±540)_:

> Inti: _prompt engineering + retrieval konteks percakapan + inferensi LLM_ (transformer, autoregressive). Alur: (1) susun system prompt = persona bahasa + aturan tingkat tutur (mis. "gunakan krama alus, hormati unggah-ungguh"); (2) gabung 20 pesan terakhir sebagai konteks; (3) panggil LLM streaming (temperature diatur per tugas: 0.3 terjemahan, ~0.7 chat); (4) untuk suara: VAD server + transkripsi Whisper. Roadmap lanjutan (opsional, bila ada dana): fine-tuning ringan (LoRA) & RLHF dengan anotator native speaker untuk bahasa daerah spesifik.

**Data / Input Utama** _(≤900 kar — ±640)_:

> Sumber jawaban: model SEA-LION/Sahabat-AI yang telah dilatih pada korpus Indonesia/ASEAN (kami tidak mengumpulkan korpus training sendiri di tahap MVP—realistis & legal). Konteks budaya: katalog **100+ bahasa** yang kami kurasi (8 dengan system prompt budaya mendalam: Indonesia, Jawa, Sunda, Batak, Bugis, Dayak, Minang, Bali). Data pengguna (percakapan) disimpan di Supabase Postgres dengan cascade delete (dukung hak hapus UU PDP). Kualitas tertinggi di Indonesia/Jawa/Sunda (data melimpah); bahasa _tail_ (Bugis/Dayak/Papua) datanya langka → mitigasi loop koreksi native speaker. Sumber data pelestarian (Fase lanjut): Wikipedia, Common Crawl, kemitraan kampus.

## 12. Technical Approach (lanjut)

**Pertimbangan Keamanan & Skalabilitas** _(≤600 kar — ±520)_:

> Keamanan: ephemeral token suara (kunci tak pernah ke browser), JWT verify + isolasi antar-user per query, TLS 1.3, security headers/CSP, secret scanning (CI), `.env` mode 600, server bind 127.0.0.1 di prod. Cascade delete = hak subjek data UU PDP. Roadmap: PSE Kominfo, ISO 27001, ITSE BSSN, pentest. Skalabilitas: stateless + Supabase pooling, siap PM2 cluster + Redis + CDN; tambah bahasa = tambah baris DB (bukan retrain), jadi skala bahasa nyaris tanpa biaya.
